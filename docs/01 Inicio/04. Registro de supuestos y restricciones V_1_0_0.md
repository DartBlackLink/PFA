## 2. Supuestos

| ID | Descripción | Categoría | Impacto | Estrategia de validación |
|---|---|---|---|---|
| SUP-01 | La línea base académica utiliza hasta 15 vehículos para la prueba principal. | Operativa | Alto | Dataset de benchmark. |
| SUP-02 | Los pedidos tendrán coordenadas o punto de referencia suficiente. | Datos | Alto | Validación de registro. |
| SUP-03 | El tráfico podrá obtenerse por API o cargarse de forma alternativa. | Técnica | Alto | Pruebas con adaptador/mocks. |
| SUP-04 | PostgreSQL cubre el volumen objetivo del MVP. | Técnica | Medio | Pruebas de carga e índices. |
| SUP-05 | Flutter Web será usado únicamente por el administrador. | Diseño | Alto | Trazabilidad actor-canal en RF/US. |
| SUP-06 | Flutter móvil será usado por el repartidor. | Diseño | Alto | Pruebas en flujo móvil. |
| SUP-07 | Los mockups se elaborarán en Figma. | Diseño | Medio | Enlace y capturas reales. |
| SUP-08 | Datos personales reales no son necesarios en desarrollo. | Privacidad | Alto | Dataset sintético. |
| SUP-09 | La elección Flutter puede aceptarse como adaptación tecnológica del proyecto. | Académica | Alto | Validación docente si RES-06 se exige literalmente. |

> **Cómo leer esta tabla:** los supuestos no son hechos confirmados. Cada uno tiene una forma concreta de validarse para evitar construir sobre una premisa falsa.

## 3. Restricciones principales

| ID | Restricción | Categoría | Severidad | Flexibilidad |
|---|---|---|---|---|
| RES-01 | Optimizar costo total de propiedad de la flota. | Económica | Alta | Baja |
| RES-02 | Considerar un plan de carbono neutral a tres años. | Ambiental | Alta | Baja |
| RES-03 | Considerar zonas sensibles e impacto ambiental/acústico. | Ambiental | Media | Media |
| RES-04 | Respetar jornadas, descansos y reglas de circulación del caso. | Social/Normativa | Alta | Baja |
| RES-05 | Presupuesto marco S/500,000 MVP y S/120,000/año operación. | Económica | Alta | Baja |
| RES-06 | La consigna propone Python + React/Vue + PostgreSQL + Leaflet/OSM. | Tecnología | Alta | Media |
| RES-07 | Interfaz comprensible en español e iconografía universal. | Cultural/UX | Media | Media |
| RES-08 | Protección de datos y autorización por necesidad de acceso. | Legal/Seguridad | Alta | Baja |
| RES-09 | Uso de georreferenciación y datos de tráfico con alternativa manual. | Datos | Alta | Baja |
| RES-10 | Considerar seguridad vial e incidentes. | Seguridad vial | Alta | Baja |
| RES-11 | Considerar condiciones climáticas que afecten la operación. | Ambiental | Media | Media |
| RES-12 | Considerar compatibilidad de vías y vehículos. | Infraestructura | Alta | Baja |

> **Cómo leer esta tabla:** resume restricciones heredadas de la consigna. La decisión Flutter se trata como una adaptación del estudiante y se registra como riesgo/decisión, no como si la consigna la exigiera.

## 4. Decisión tecnológica frente a RES-06

| Aspecto | Consigna | Propuesta del estudiante | Tratamiento |
|---|---|---|---|
| Backend | Python FastAPI/Django | FastAPI/Python | Alineado |
| Frontend Web | React/Vue | Flutter Web | Adaptación |
| Aplicación móvil | No definida explícitamente | Flutter móvil | Extensión de canal para repartidor |
| Base de datos | PostgreSQL | PostgreSQL | Alineado |
| Mapas | Leaflet/OSM o alternativa | Proveedor cartográfico compatible con Flutter | Adaptación de cliente |

> **Cómo leer esta tabla:** muestra exactamente qué cambia respecto de la referencia tecnológica de la consigna. La adaptación no altera los RF/RNF, pero debe poder justificarse ante el docente.
