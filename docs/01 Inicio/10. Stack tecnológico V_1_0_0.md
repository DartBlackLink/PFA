## 3. Propuesta real del estudiante

| Capa | Tecnología | Justificación |
|---|---|---|
| Web administrador | Flutter Web / Dart | Unifica lenguaje de UI con móvil y permite una app administrativa independiente. |
| Móvil repartidor | Flutter / Dart | Experiencia móvil específica para operación de campo. |
| Backend | FastAPI / Python | Adecuado para API y ecosistema de optimización. |
| Base de datos | PostgreSQL | Modelo relacional e integridad. |
| API | REST/JSON + OpenAPI | Contrato común para Web y móvil. |
| Diseño | Figma | Mockups y prototipos de ambos canales. |
| Gestión | Jira + Git | Scrum, trazabilidad y versiones. |

> **Resumen de la tabla:** esta es la decisión que debe reflejarse en arquitectura, historias y repositorio. Flutter Web y móvil son proyectos separados.

## 4. Diferencia respecto de la consigna tecnológica

| Elemento | Línea base de la consigna | Decisión del alumno | Estado |
|---|---|---|---|
| Backend | Python FastAPI/Django | FastAPI | Alineado |
| Frontend | React/Vue | Flutter Web | Adaptación |
| Móvil | No especificado como app separada | Flutter móvil | Extensión |
| BD | PostgreSQL | PostgreSQL | Alineado |
| Mapas | Leaflet/OSM o alternativa | SDK/proveedor compatible con Flutter | Adaptación de cliente |

> **Resumen de la tabla:** hace visible la adaptación en lugar de ocultarla. Si el docente exige RES-06 literalmente, este punto debe validarse antes de implementación avanzada.

## 5. Organización propuesta

```text
apps/
  ecologistica_web/       # Flutter Web administrador
  ecologistica_mobile/    # Flutter móvil repartidor
backend/
  api/                    # FastAPI + optimizador
database/
  migrations/
docs/
  01 Inicio/
  02 Planificación/
```

> **Resumen:** separar proyectos reduce acoplamiento de navegación y despliegue, mientras la API evita duplicar reglas de negocio.
