## 2. Objetivo del documento

Determinar y justificar el enfoque de gestión más adecuado para el proyecto, considerando que la solución combina requisitos funcionales definidos, restricciones reales, integración con servicios geográficos y de tráfico, un algoritmo de optimización para VRPTW/Green VRP, requisitos de sostenibilidad y entregas incrementales durante el curso.

La escala utilizada es:

- **1:** comportamiento predominantemente predictivo.
- **2:** baja necesidad de adaptación.
- **3:** equilibrio entre predictibilidad y adaptación.
- **4:** alta necesidad de adaptación.
- **5:** comportamiento altamente adaptativo.

## 5. Enfoque seleccionado

Se selecciona un **enfoque Ágil/Adaptativo**, con **Scrum** como marco operativo para la planificación de iteraciones y **PMBOK 7.ª edición** como referencia de gobernanza, trazabilidad, gestión de interesados, riesgos y adaptación.

## 6. Justificación técnica

1. **El problema no tiene una única solución evidente.** La calidad de una ruta depende simultáneamente de distancia, tiempo, consumo, emisiones y penalizaciones por ventanas de tiempo.
2. **La solución requiere experimentación.** La consigna admite distintas metaheurísticas, por lo que el equipo debe comparar resultados y ajustar parámetros.
3. **La información operacional cambia.** Nuevos pedidos, cancelaciones, accidentes y averías obligan a reoptimizar.
4. **La construcción es incremental.** Primero se consolidan requisitos y datos, luego gestión de flota/pedidos, después optimización, visualización, indicadores y reportes.
5. **Los RNF deben verificarse continuamente.** Rendimiento, seguridad, accesibilidad, disponibilidad y escalabilidad no pueden evaluarse únicamente al final.
6. **PMBOK 7 permite tailoring.** Se aplican principios de adaptación del enfoque, entrega de valor, participación de interesados, gestión de incertidumbre y medición.

## 8. Criterios para revisar la decisión

La decisión deberá reconsiderarse si ocurre alguna de las siguientes condiciones:

- el docente modifica sustancialmente el alcance;
- una integración externa impide cumplir los tiempos establecidos;
- el algoritmo no alcanza los límites de rendimiento;
- las restricciones normativas obligan a rediseñar módulos;
- se detecta que una parte del alcance requiere una planificación más predictiva.

## 9. Conclusión

El perfil de **3.8/5** evidencia una necesidad alta de adaptación. Por ello, el proyecto será gestionado de manera **Ágil/Adaptativa**, manteniendo documentación, trazabilidad, métricas y control de riesgos para satisfacer las exigencias académicas y técnicas de la consigna.
