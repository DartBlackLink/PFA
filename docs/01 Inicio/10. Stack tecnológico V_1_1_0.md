## Alcance y fuentes de evidencia

EcoLogística Huancayo es la propuesta del estudiante; el escenario de evaluación sigue siendo Lima (San Juan de Lurigancho, El Agustino, Santa Anita y Ate), con RF-01 a RF-10, RNF-01 a RNF-07 y RES-01 a RES-12. Los mapas de Huancayo son una demo adicional.

Arquitectura objetivo: Web ADMIN con preferencias CLIENTE (RF-09), móvil REPARTIDOR, FastAPI y PostgreSQL. Este documento define el diseño y sus criterios de validación. Las acciones de implementación, Jira, Figma y evidencias se coordinan en la guía de ajustes.

## Comparación cualitativa de alternativas

Escala: baja/media/alta expresa adecuación razonada para este proyecto, no una medición experimental. Las tarifas del presupuesto son supuestos separados de esta comparación.

| Criterio | MERN | FastAPI + React + PostgreSQL | Spring + Angular + PostgreSQL | FastAPI + Flutter + PostgreSQL |
| --- | --- | --- | --- | --- |
| Optimización Python | Requiere servicio Python adicional | Directa en backend | Requiere integración con motor Python | Directa en backend |
| Integridad relacional | MongoDB exige diseño alternativo | Alta con PostgreSQL | Alta con PostgreSQL | Alta con PostgreSQL |
| Web semántica/accesibilidad | Revisión DOM estándar | Revisión DOM estándar | Revisión DOM estándar | Requiere validar semántica, teclado y lectores |
| Reutilización móvil | Otro cliente o framework | Otro cliente o framework | Otro cliente o framework | Alta en componentes Dart; despliegues separados |
| Curva de aprendizaje del estudiante | No medida | No medida | No medida | Existe avance Flutter; experiencia no cuantificada |
| Infraestructura | API Node más motor Python | API Python y BD | JVM y BD | API Python y BD |
| Eficiencia energética | Medir API y payload | Medir API y payload | Medir JVM y payload | Medir bundle Web, render y API |
| Alineación RES-06 | Frontend React; backend diferente | Directa | Backend/frontend diferentes | Frontend Flutter es adaptación |

## Decisión ADR-02

Se conserva FastAPI/Python y PostgreSQL por integración con algoritmos y modelo relacional. Se conserva Flutter como decisión del estudiante aprovechando el código existente y componentes compartibles con móvil. El costo es validar accesibilidad y carga inicial Web, además de justificar la desviación de React/Vue. Validación de la decisión: presentar ADR-02 y conservar la respuesta docente en el expediente de cierre. Si se exige el stack literal, se reemplaza el cliente Web conservando contrato API y dominio.

Mapas: flutter_map/OSM para visualización; geometría y matrices mediante adaptador backend a proveedor de rutas. OSRM ofrece recorridos usados en el prototipo; no es el motor metaheurístico exigido ni acredita tráfico en tiempo real. Tráfico requiere proveedor autorizado o carga manual fechada; disponibilidad y acceso a Waze/Google no se presumen. El algoritmo genético pertenece al backend.

## Organización objetivo del repositorio único

```text
README.md
.gitignore
docs/
  01 Inicio/
  02 Planificación/
  03 Implementación/        # Cuatro documentos con plan y criterios S1/S2
apps/
  ecologistica_web/         # ADMIN y área CLIENTE limitada a RF-09
  ecologistica_mobile/      # REPARTIDOR
backend/                   # FastAPI, optimización y adaptadores
database/migrations/       # O backend/migrations, una sola fuente canónica
tests/
```

La estructura anterior es propuesta, no estructura existente. El código inspeccionado está fuera de PFA y contiene un único proyecto Flutter con backend interno. Su integración y separación se harán en Implementación con comprobación de configuración, secretos, migraciones y pruebas. Las variables del cliente son públicas tras compilación: no deben contener claves privadas.

## Criterios de aceptación de la decisión

Benchmark RNF-01, carga RNF-04, teclado/lector/contraste RNF-03 y tamaño/tiempo de carga Web. Login RN-023 con estado compartido en PostgreSQL, API como autoridad del bloqueo y contador Flutter sincronizado. Secretos exclusivamente backend; las variables compiladas del cliente son públicas. Ajustar infraestructura con mediciones y registrar resultados en el expediente de QA.
