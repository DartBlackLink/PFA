## 2. Criterio de especificación

Los RNF se expresan mediante escenarios de calidad: **Fuente → Estímulo → Entorno → Artefacto → Respuesta → Medida**.  
Las métricas no presentes literalmente en la consigna se declaran como **criterios internos de aceptación del proyecto**, no como hechos externos.

## 4. Controles por RNF

### RNF-01 Rendimiento
- Benchmark con 25, 50, 100 y 150 pedidos.
- Medición separada de carga de datos, optimización y serialización de resultados.
- Registro de tiempo total y calidad de solución.

### RNF-02 Seguridad
- Validación server-side.
- Consultas parametrizadas/ORM.
- Protección contra XSS y CSRF según arquitectura.
- Autenticación robusta y autorización por rol.
- Secretos fuera del repositorio.
- Logs sin credenciales ni datos sensibles innecesarios.

### RNF-03 Accesibilidad
- Contraste adecuado.
- Navegación por teclado.
- Etiquetas semánticas.
- Estados de foco visibles.
- Alternativas textuales.
- Formularios con mensajes de error comprensibles.

### RNF-04 Escalabilidad
- Índices sobre claves de búsqueda frecuentes.
- Paginación de listados.
- Operaciones costosas fuera del render del cliente.
- Pruebas con el volumen objetivo.

### RNF-05 Usabilidad
- Modo conductor simplificado.
- Iconos grandes y estados claros.
- Evitar sobrecarga informativa.
- Pruebas de tareas críticas.

### RNF-06 Disponibilidad
- Backups.
- Manejo de fallos de servicios externos.
- Degradación controlada del mapa/tráfico.
- Registro de incidentes.

### RNF-07 Documentación
- README de instalación.
- Manual de usuario.
- Manual de administrador.
- OpenAPI/Swagger.
- Arquitectura y base de datos.
- Estrategia de pruebas y variables de entorno.

## 5. Trazabilidad
