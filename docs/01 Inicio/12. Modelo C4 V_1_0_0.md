## 2. Decisión arquitectónica

La solución tendrá **dos aplicaciones cliente separadas**:

1. **EcoLogística Web:** desarrollada con Flutter Web.
2. **EcoLogística Mobile:** desarrollada con Flutter para dispositivos móviles.

Ambas se comunican con una **API backend común**. La lógica crítica de negocio, persistencia, seguridad, cálculo de indicadores y motor de optimización se centralizan en backend.

Esto evita duplicar reglas de negocio en los dos clientes y permite que cada aplicación tenga navegación, componentes, permisos y despliegue propios.

## 9. Flujo crítico de optimización

```mermaid
sequenceDiagram
    participant O as Operador
    participant W as Flutter Web
    participant A as FastAPI
    participant DB as PostgreSQL
    participant OP as Optimizador

    O->>W: Solicita optimización
    W->>A: POST /rutas/optimizar
    A->>DB: Obtiene pedidos, flota y conductores
    A->>OP: Construye problema VRPTW/Green VRP
    OP-->>A: Solución y métricas
    A->>DB: Persiste rutas y detalles
    A-->>W: Resultado
    W-->>O: Mapa + KPIs
```

## 10. Flujo móvil del conductor

```mermaid
sequenceDiagram
    participant C as Conductor
    participant M as Flutter Mobile
    participant A as FastAPI
    participant DB as PostgreSQL

    C->>M: Abre ruta asignada
    M->>A: GET /mi-ruta
    A->>DB: Consulta asignación vigente
    DB-->>A: Ruta + entregas
    A-->>M: Datos de ruta
    M-->>C: Muestra recorrido y pendientes

    C->>M: Reporta incidente
    M->>A: POST /incidentes
    A->>DB: Registra incidente
    A-->>M: Confirmación
```

## 11. Fronteras de seguridad

- HTTPS entre ambos clientes y backend.
- Autenticación común con autorización por rol/recurso.
- Tokens almacenados de forma segura según plataforma.
- Validación server-side obligatoria.
- La base de datos no es accesible directamente desde Flutter Web ni Flutter móvil.
- Secretos de servicios externos permanecen en backend.
- No incluir claves privadas en repositorios de Flutter.

## 12. Decisión final

La arquitectura queda alineada con la decisión de desarrollo:

> **dos aplicaciones Flutter independientes (Web y móvil) conectadas a una API backend común**, con el motor de optimización ejecutándose en backend y PostgreSQL como persistencia central.
