## 3. Función objetivo conceptual

```text
CostoTotal =
  w1 * DistanciaTotal +
  w2 * TiempoTotal +
  w3 * ConsumoCombustible +
  w4 * EmisionesCO2 +
  w5 * PenalizacionTardanza
```

> **Resumen:** los pesos se documentan por experimento. Las restricciones duras —capacidad, disponibilidad o permisos— no se “compensan” con pesos: deben cumplirse.

## 4. Trazabilidad

```mermaid
flowchart LR
    RN[Regla de negocio] --> RF[Requisito funcional]
    RN --> RNF[Requisito no funcional]
    RF --> US[Historia de usuario]
    RNF --> EN[Enabler]
    US --> TEST[Prueba]
    EN --> TEST
```

> **Resumen del diagrama:** la trazabilidad evita implementar historias desconectadas de la consigna. Cada prueba debe poder remontarse a un RF/RNF.

## 5. Control de cambios

Si una regla cambia, revisar requisito, historia/enabler, modelo de datos, criterios BDD, pruebas y documentación antes de cerrar el cambio.
