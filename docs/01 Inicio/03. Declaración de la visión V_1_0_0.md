## 2. Visión del producto

**Para** los responsables de operaciones logísticas, conductores y clientes vinculados a DistriRápido S.A.C.,  
**quienes** necesitan reducir recorridos innecesarios, retrasos, consumo de combustible, emisiones y penalizaciones por incumplimiento de ventanas de entrega,  
**EcoLogística Huancayo**  
**es un** sistema de optimización y gestión de rutas de última milla compuesto por una aplicación **Flutter Web** y una aplicación **Flutter móvil** desarrolladas como clientes separados,  
**que** registra recursos y pedidos, calcula rutas sostenibles mediante metaheurísticas, reoptimiza ante cambios, visualiza recorridos y cuantifica el impacto económico y ambiental,  
**a diferencia de** la planificación secuencial o manual de rutas sin evaluación integrada de ventanas de tiempo, tráfico, consumo y emisiones,  
**nuestro producto** integra VRPTW, criterios Green VRP, sostenibilidad, visualización geográfica, reoptimización y reportes sobre una API común, manteniendo una aplicación web y una aplicación móvil Flutter como productos cliente separados.

## 3. Problema que se busca transformar

La línea base indicada por la consigna presenta:

- más de 250 entregas diarias;
- 15 camionetas;
- combustible y mantenimiento equivalentes al 35% de los costos totales;
- aproximadamente 3.5 toneladas de CO₂ mensuales;
- 22% de entregas fuera del horario acordado.

La visión es convertir esa operación en un proceso digital medible donde las decisiones de ruteo puedan justificarse con datos.

## 4. Propuesta de valor

1. **Eficiencia operacional:** reducir distancia, tiempo, combustible y penalizaciones.
2. **Sostenibilidad:** cuantificar CO₂ y disponer de un plan de compensación.
3. **Adaptabilidad:** recalcular rutas ante eventos operativos.
4. **Visibilidad:** mostrar rutas y KPIs en interfaces comprensibles.
5. **Trazabilidad:** conservar evidencia de decisiones, reportes y resultados.
6. **Calidad:** aplicar ISO/IEC 25010, OWASP Top 10 y WCAG 2.1.

## 5. Objetivos estratégicos y KPIs

## 6. Principios de producto

- El optimizador no debe ignorar restricciones de capacidad o ventanas de tiempo.
- La sostenibilidad es parte del cálculo y no un reporte aislado.
- Los datos de clientes y conductores se tratarán bajo principios de mínimo privilegio.
- La experiencia administrativa se implementará en **Flutter Web** y la experiencia del conductor en una **aplicación Flutter móvil independiente**.
- El sistema debe tolerar datos externos incompletos mediante mecanismos manuales previstos por la consigna.
- Toda métrica presentada debe poder rastrearse hasta datos de entrada y reglas de cálculo.

## 7. Resultado esperado

Al finalizar el PFA, el proyecto deberá demostrar un flujo completo: **registro de datos → optimización → visualización → seguimiento → medición de impacto → reporte**, con documentación suficiente para justificar cada decisión técnica.
