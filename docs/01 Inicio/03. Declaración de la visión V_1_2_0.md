## 2. Plantilla de visión

| Elemento | Declaración |
|---|---|
| Para | Administradores, repartidores y clientes de DistriRápido S.A.C. |
| Quienes | Necesitan planificar y ejecutar entregas reduciendo distancia, tardanzas, combustible y emisiones. |
| Producto | EcoLogística Huancayo. |
| Categoría | Sistema de optimización de rutas con aplicación Web administrativa y aplicación móvil para repartidor. |
| Beneficio clave | Centraliza gestión, optimización, operación y medición de sostenibilidad. |
| A diferencia de | Planificación manual o secuencial sin optimización multicriterio ni medición ambiental integrada. |
| Diferenciador | Integra VRPTW/Green VRP, reoptimización, mapa, movilidad del repartidor y métricas ambientales. |

## 3. Usuarios y canales

| Usuario | Aplicación | Funciones principales |
|---|---|---|
| Administrador | Flutter Web | Flota, repartidores, pedidos, clientes, optimización, mapa, KPIs, reportes y configuración. |
| Repartidor | Flutter móvil | Ruta asignada, entregas pendientes, estado de entrega, alertas e incidentes. |
| Cliente | Área restringida Web (RF-09) | Horarios, referencias y restricciones de acceso propias. |

## 4. Objetivos estratégicos y KPIs

| Objetivo | KPI | Meta inicial |
|---|---|---|
| Optimización utilizable | Tiempo de cálculo | ≤45 s para 150 pedidos/15 vehículos. |
| Adaptación operativa | Tiempo de reoptimización | <30 s. |
| Puntualidad | % entregas dentro de ventana | Medir y comparar contra línea base. |
| Sostenibilidad | kg CO₂/ruta y CO₂ evitado | Disponible por ruta y periodo. |
| Eficiencia económica | Combustible y ahorro estimado | Disponible en dashboard/reporte. |
| Disponibilidad | Uptime operativo | ≥99.5% de 05:00 a 22:00. |
| Accesibilidad | Verificación WCAG | Nivel AA en criterios aplicables. |

## 5. Principios de producto

- El administrador toma decisiones desde Flutter Web; el cliente registra preferencias en un área restringida Web de RF-09.
- El repartidor opera desde Flutter móvil.
- El motor de optimización se ejecuta en backend, no en el dispositivo móvil.
- No se exponen credenciales ni acceso directo a PostgreSQL desde Flutter.
- La sostenibilidad forma parte del cálculo y del reporte.
- Los mockups se diseñan en Figma antes de consolidar la UI.

## Cobertura de UX y estado de los mockups

El diseño cubre Web y móvil por rol; las ocho imágenes locales sirven como referencia visual. Los formularios deben mostrar sus campos, validaciones, estados vacíos, errores y permisos.

| Flujo | Especificación de UX |
| --- | --- |
| Login Web/móvil | Email/contraseña; error genérico; bloqueo RN-023 con contador 5 s, 10 s y 05:00, botón deshabilitado y reactivación al vencer |
| Flota | Placa, tipo, capacidad, consumo, factor, año y estado; duplicado y valores inválidos |
| Repartidores | DNI, licencia/categoría, experiencia, contacto, disponibilidad y origen; campos separados |
| Pedidos | Cliente, dirección/referencia, coordenadas, peso/volumen, ventana, prioridad y producto |
| Ruta/detalle/incidente | Lista y mapa, entrega propia, incidente, sin conexión y sincronización |
| Preferencias/PDF | Preferencias propias y salida PDF con periodo, parámetros y fuentes |

Los mockups se contrastan con los campos y estados de interacción descritos en esta sección. Usabilidad: RNF-05; accesibilidad: RNF-03.
